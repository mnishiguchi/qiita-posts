## はじめに

先日、組込みシステム技術に関するサマーワークショップ [SWEST28](https://swest.toppers.jp/phx/event) に参加しました。

https://swest.toppers.jp/phx/event

そこで、UIAPを開発されている埋田祐希さんによる、[UIAPduinoを使った組込み開発の講習](https://www.uiap.jp/en/event#swest-28)に参加しました。

講習では [UIAPduino Pro Micro CH32V003](https://www.uiap.jp/en/uiapduino/pro-micro/ch32v003/v1dot4) を使い、さらに開発中の [UIAPduino Pro Micro CH32V006](https://www.uiap.jp/en/uiapduino/pro-micro/ch32v006/v1dot1) もいただきました。

SWEST28のあと、まずCH32V003を使って[簡単なゲーム](https://github.com/YuukiUmeta-UIAP/UIAP-Devices/pull/12)を作り、UIAPやElixirのコミュニティー、SWEST参加者のみなさんに共有しました。

そのとき雑談の中で、「UIAPduinoでAtomVMが動いたら面白そう」という話が出ました。

私は普段ElixirやAtomVMを使っていますが、AtomVMの内部実装にも、CH32V006の低い層の仕組みにも詳しくありません。

それでも興味があったので、ChatGPTやCodexに調査を手伝ってもらいながら試してみることにしました。

試行錯誤しながら進めた結果、まだ実験的な段階ではありますが、CH32V006上でElixirのコードを動かし、Lチカまで確認できました。

---

## UIAPとは

UIAPduinoは、小型で安価なArduino互換の開発基板です。

https://www.uiap.jp/uiapduino/

UIAPduinoの2種類に加えて、比較用にXIAO ESP32S3も載せてみます。

| 基板                           | Flash |  SRAM |
| ---------------------------- | ----: | ----: |
| UIAPduino Pro Micro CH32V003 |  16KB |   2KB |
| UIAPduino Pro Micro CH32V006 |  64KB |   8KB |
| XIAO ESP32S3                 |   8MB | 512KB |

こうして並べてみると、CH32V006もかなり小さいことが分かります。

それでもCH32V003よりは余裕があります。そこで、AtomVMの機能を必要最低限まで絞れば、CH32V006なら動かせるのではないかと考えました。

---

## AtomVMとは

AtomVMは、ElixirやErlangのコードをマイコン上で動かすための軽量な仮想機械です。

ESP32などの組込み環境で利用でき、限られたFlashやRAMでも動くように小さく作られています。

https://atomvm.org/

---

## CH32V006ではさらに小さくする必要がある

CH32V006はFlash 64KB、SRAM 8KBと、AtomVMを動かすにはかなり限られた環境です。

そこで今回は、通常のAtomVMをそのまま載せるのではなく、機能を必要最低限まで絞った構成にしました。

まずは、

```text
AtomVMが起動する
↓
Elixirのコードを実行する
↓
GPIOでLチカする
```

ところまでを目標にしました。

そのため、今回の実験ではAtomVMの機能をかなり限定しています。

---

## LLMと一緒に開発する

私はAtomVMの内部実装やCH32V006について詳しくないため、ChatGPTやCodexに調査や実装を手伝ってもらいながら進めました。

調査、実装、ビルド、測定、実機確認を繰り返し、その過程で試したことや判断した理由を作業記録やADRとして残しました。

一つずつ確認しながら進めることで、知らない領域でも少しずつ形にしていきました。

AtomVMの起動

## Lチカしてみる

ここからは、実際にCH32V006でAtomVMを動かし、ElixirでLチカするまでの手順を紹介します。

Linux環境を前提に進めます。

### 1. 開発環境を準備する

今回使用した主な環境は次のとおりです。

```text
Erlang/OTP 28
Elixir 1.19
GNU Make
RISC-V GCC
RISC-V binutils
newlib
```

私の環境では、次のコマンドで確認しました。

```bash
erl -noshell \
  -eval 'io:format("OTP ~s~n", [erlang:system_info(otp_release)]), halt().'

elixir --version
make --version
riscv64-unknown-elf-gcc --version
riscv64-unknown-elf-readelf --version
```

### 2. ch32funとminichlinkを準備する

CH32V006の土台として、[ch32fun](https://github.com/cnlohr/ch32fun)を使います。

今回は、動作確認した版を固定して使いました。

```bash
git clone https://github.com/cnlohr/ch32fun.git /tmp/ch32fun

git -C /tmp/ch32fun checkout \
  618bba58c615ed29dc99e6ea92d869c914b6a8c0
```

CH32V006への書き込みや端末表示に使う`minichlink`もビルドします。

```bash
make -C /tmp/ch32fun/minichlink
```

UIAPduinoをUSBで接続すると、私の環境では次のように認識されました。

```bash
lsusb | grep -i 1209:b806
```

```text
ID 1209:b806 Generic CNLohr RV003 RVSWDIO Programmer Customized for UIAPduino
```

### 3. まずAtomVMをビルドする

最初に、リポジトリーに用意した最小構成のLチカをビルドしてみます。

AtomVMのリポジトリー直下で実行します。

```bash
make -C src/platforms/ch32v006 \
  CH32FUN=/tmp/ch32fun/ch32fun \
  clean image
```

今回の構成では、おおまかに次の流れでファームウェアを作ります。

```text
Erlang
↓
BEAM
↓
RISC-V向けに事前コンパイル
↓
AtomVMと結合
↓
ファームウェア
```

ビルドすると、私の環境では次の結果になりました。

```text
Validated build/ch32v006_minimal.beam: 1096 bytes of rv32ec_zmmul code
```

Flash使用量は、

```text
Verified atomvm_ch32v006.bin: 56200 / 63488 bytes (7288 bytes free)
```

でした。

62KBほどしか使えないため、かなりギリギリです。

### 4. CH32V006へ書き込む

できたファームウェアを実機へ書き込みます。

```bash
make -C src/platforms/ch32v006 \
  CH32FUN=/tmp/ch32fun/ch32fun \
  MINICHLINK=/tmp/ch32fun/minichlink \
  FLASH_IMAGE=build/images/AtomVM-uiapduino-pro-micro-ch32v006.bin \
  flash-uiap
```

正常に書き込めると、

```text
Detected CH32V006
Writing image

Image written.
```

と表示されます。

この時点では、基板上の橙色LEDが、

```text
100ms 点灯
900ms 消灯
```

を繰り返します。

まずはこれで、AtomVMがCH32V006の実機上で動くことを確認できました。

### 5. ElixirでLチカを作る

次は、実際にElixirのコードを動かしてみます。

AtomVMのリポジトリーとは別の場所にMixプロジェクトを作ります。

```bash
mix new uiap_blink --module UIAPBlink
cd uiap_blink
```

`mix.exs`にExAtomVMを追加します。

```elixir
def project do
  [
    app: :uiap_blink,
    version: "0.1.0",
    elixir: "~> 1.19",
    deps: deps(),
    atomvm: [start: UIAPBlink]
  ]
end

defp deps do
  [
    {:exatomvm,
     git: "https://github.com/atomvm/ExAtomVM",
     branch: "main",
     runtime: false}
  ]
end
```

`lib/uiap_blink.ex`は次のようにしました。

```elixir
defmodule UIAPBlink do
  @compile {:no_warn_undefined, [:gpio, :ch32v006]}

  @led 35

  def start do
    :gpio.init(@led)
    :gpio.set_pin_mode(@led, :output)
    loop(:high)
  end

  defp loop(level) do
    :gpio.digital_write(@led, level)
    :ch32v006.delay_ms(500)
    loop(toggle(level))
  end

  defp toggle(:high), do: :low
  defp toggle(:low), do: :high
end
```

処理は単純です。

```text
LEDを点灯
↓
500ms待つ
↓
LEDを消灯
↓
500ms待つ
↓
繰り返す
```

コンパイルします。

```bash
mix deps.get
mix compile
```

すると、

```text
_build/dev/lib/uiap_blink/ebin/Elixir.UIAPBlink.beam
```

ができます。

### 6. Elixir入りのファームウェアをビルドする

今回のCH32V006版では、`mix atomvm.packbeam`で`.avm`を作る方式は使いません。

代わりに、`mix compile`でできたBEAMをAtomVMのファームウェアへ直接組み込みます。

```text
Elixir
↓
BEAM
↓
RISC-V向けに事前コンパイル
↓
AtomVMと結合
↓
ファームウェア
```

AtomVMのリポジトリーへ戻り、BEAMを指定してビルドします。

```bash
make -C src/platforms/ch32v006 \
  CH32FUN=/tmp/ch32fun/ch32fun \
  START_BEAM_INPUT=/path/to/uiap_blink/_build/dev/lib/uiap_blink/ebin/Elixir.UIAPBlink.beam \
  IMAGE_BASENAME=AtomVM-uiapduino-pro-micro-ch32v006-uiap-blink \
  image
```

私の環境では、

```text
Validated build/Elixir.UIAPBlink.beam: 2824 bytes of rv32ec_zmmul code
```

となりました。

ファームウェア全体では、

```text
Verified atomvm_ch32v006.bin: 58672 / 63488 bytes (4816 bytes free)
```

でした。

比較すると次のようになります。

| 内容           |     Flash使用量 |
| ------------ | -----------: |
| 最小Erlang Lチカ | 56,200 bytes |
| Elixir Lチカ   | 58,672 bytes |

Elixir版では残り4,816 bytesです。

改めて、かなり小さな世界だと分かります。

### 7. Elixir入りのファームウェアを書き込む

できたファームウェアを実機へ書き込みます。

```bash
make -C src/platforms/ch32v006 \
  CH32FUN=/tmp/ch32fun/ch32fun \
  MINICHLINK=/tmp/ch32fun/minichlink \
  FLASH_IMAGE=build/images/AtomVM-uiapduino-pro-micro-ch32v006-uiap-blink.bin \
  flash-uiap
```

書き込み後、LEDの動きが、

```text
100ms 点灯
900ms 消灯
```

から、

```text
500ms 点灯
500ms 消灯
```

に変わりました。

これで、CH32V006上でElixirのコードが実際に動いていることを確認できました。

### 8. AtomVMの起動を確認する

最後に、SWIO経由でAtomVMの起動メッセージも確認します。

```bash
make -C src/platforms/ch32v006 \
  CH32FUN=/tmp/ch32fun/ch32fun \
  MINICHLINK=/tmp/ch32fun/minichlink \
  monitor-uiap
```

実機から、

```text
Terminal started

AVM CH32V006 boot
```

と表示されました。

これで、

```text
Elixir
↓
BEAM
↓
AtomVM
↓
RISC-V向け事前コンパイル
↓
CH32V006
↓
GPIO
↓
Lチカ
```

という一連の流れを実機で確認できました。

## わかったこと

今回の実験では、CH32V006のような小さなマイコンでも、AtomVMの機能を必要最低限まで絞ることで、Elixirのコードを実行できることを確認できました。

特に、

```text
Elixir
↓
BEAM
↓
AtomVM
↓
RISC-V
↓
CH32V006
```

という一連の流れを実機で確認できたことが、今回の大きな成果です。

もちろん、まだ通常のAtomVMと同じように使える段階ではありません。

それでも、Flash 64KB、SRAM 8KBという限られた環境でも、AtomVMを動かせる可能性が見えてきました。


---

## 現時点での制限

今回のCH32V006向けAtomVMは、まだ実験段階です。

現時点では、主に次のような制限があります。

* FlashやRAMに余裕がほとんどない
* AtomVMの機能をかなり限定している
* 起動するBEAMをファームウェアへ直接組み込んでいる
* 通常のAtomVMで使える機能の多くはまだ利用できない
* アプリを書き換えるたびにファームウェア全体をビルドし直す必要がある

そのため、ESP32版のAtomVMと同じ感覚で使える状態ではありません。

今のところは、CH32V006でAtomVMをどこまで小さく動かせるかを試している段階です。

---

## 今後

今後は、Lチカ以外の基本的な機能も少しずつ試していきたいです。

たとえば、

* GPIO入力
* ボタン
* UART
* ADC
* I2C
* SPI

などです。

また、限られたFlashやRAMの中で、どこまでElixirらしいコードを書けるのかも試してみたいです。

CH32V006をESP32の小さい版として考えるのではなく、この大きさだからこそできるAtomVMの使い方を探していければと思っています。

## おわりに

今回、UIAPduino Pro Micro CH32V006上で、最小構成のAtomVMからElixirのLチカまで実機で確認できました。

私はAtomVMの内部実装やCH32V006に詳しいわけではありませんが、LLMに助けてもらいながら、調査、実装、測定、実機確認を一つずつ積み重ねることで、ここまで進めることができました。

SWEST28でUIAPduinoに触れたことや、その後のコミュニティーでの何氣ない会話が、今回の実験につながりました。

まだ実験段階ではありますが、CH32V006でもAtomVMを動かせる可能性が見えてきたので、引き続き少しずつ試していきたいと思います。
