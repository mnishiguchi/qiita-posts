## 回路を機能ごとに分けて考える

音声回路を整理してみると、大きく次のような機能に分けられることが分かりました。

```text
XIAO ESP32-C5
  │ PWM 音声出力
  ▼
RC ローパスフィルタ
  │
  ▼
音量調整（可変抵抗）
  │
  ▼
音声アンプ（NJM2113D）
  │
  ▼
スピーカー
```

このほかにも、音声信号の直流成分を取り除くコンデンサや、アンプの電源を安定させるためのコンデンサなどがあります。

それぞれの仕組みを LLM に説明してもらいながら調べていくうちに、部品の役割や配線の意味が少しずつ分かるようになりました。

特に興味深かったのは、抵抗とコンデンサを組み合わせた PWM フィルタと、コンデンサによる電源の安定化です。同じ部品でも、使い方によって役割が変わることが印象に残りました。

### PWM で音声信号を作る

まず學んだのが、PCM（Pulse Code Modulation）と PWM（Pulse Width Modulation）の違いです。

PCM は音声を数値で表す方式で、PWM は GPIO の HIGH / LOW を高速に切り替え、その時間の割合（デューティ比）で値を表す方式です。

今回の実験では、8-bit の PCM データを使用しています。各サンプルは `0〜255` の値を持ち、`128` 付近が波形の中心に相当します。

ESP32-C5 では、この PCM の値に応じて PWM のデューティ比を変化させ、GPIO から出力しています。

![pwm-duty.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/82804/48cea96f-a6c0-4bd4-9a55-2efe165a4bd5.png)

例えば、デューティ比が 25% なら HIGH の時間は全体の 1/4、75% なら 3/4 になります。

ここで少しややこしかったのが、PCM のサンプルレートと PWM の周波数は別物だという点です。

- **PCM のサンプルレート**：1 秒間に何個の音声サンプルを再生するか。最初の実験では 8 kHz、2 台でのデュエットでは 16 kHz を使用しました。
- **PWM の周波数**：GPIO の HIGH / LOW を 1 秒間に何周期繰り返すか。最初の実験では約 156 kHz でした。

つまり、PCM の値を一定間隔で読み出し、その値に応じて高速な PWM のデューティ比を更新しています。

ただし、GPIO から出力されるのは、まだ HIGH / LOW を繰り返すパルス信号です。これを音声として扱いやすい信号に近づけるために、次の RC ローパスフィルタを使います。

### RC フィルタで PWM を滑らかにする

今回、特に興味深かったのが、RC ローパスフィルタです。

RC フィルタは、抵抗（R：Resistor）とコンデンサ（C：Capacitor）を組み合わせたアナログフィルタです。

アナログフィルタとは、プログラムで数値を計算するのではなく、電子部品の電氣的な性質を利用して、信号に含まれる周波数成分を調整する回路のことです。

今回使用したローパスフィルタ（Low-Pass Filter）は、低い周波数の成分を比較的通しやすく、高い周波数の成分を弱める働きをします。

PWM は GPIO の HIGH / LOW を高速に切り替える信号ですが、そのままでは高速なスイッチング成分が含まれています。RC フィルタを通すことで、この高周波成分を弱め、音声に必要な比較的ゆっくりした電圧の変化を取り出します。

今回の回路では、10 kΩ の抵抗（R1）と 1 nF のコンデンサ（C5）を使用しました。

```text
PWM ── R1（10 kΩ）──┬── フィルタ後の信号
                   │
                 C5（1 nF）
                   │
                  GND
```

抵抗は電流の流れを制限し、コンデンサは電氣を蓄えたり放出したりします。コンデンサの充放電には時間がかかるため、PWM の高速な電圧変化が緩やかになります。

![rc-filter-ja.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/82804/a9bf0d53-db46-4f34-93e0-5430c1ec1b8f.png)

この組み合わせでは、理論上のカットオフ周波数は約 15.9 kHz になります。高い周波数ほど減衰しますが、1 段の RC フィルタですべての高周波成分を取り除けるわけではありません。

最初は抵抗とコンデンサをそれぞれ独立した部品として考えていましたが、この 2 つを組み合わせるだけで、プログラムを使わずに信号の性質を変えられることが新鮮でした。

### 可変抵抗で音量を調整する

RC フィルタを通った音声信号は、10 kΩ の半固定抵抗（可変抵抗）で音量を調整します。

可変抵抗は、つまみを回すことで抵抗値を変えられる部品です。今回使用したものには端子が3本あり、それぞれ次のようにつなぎます。

- **入力端子**：RC フィルタからの音声信号
- **GND 端子**：GND に接続
- **中央端子（ワイパー）**：音量を調整した信号をアンプへ送る

```text
RC フィルタからの音声信号
           │
           ▼
      ┌─────────┐
      │ 10 kΩ   │
      │ 可変抵抗 ├── ワイパー → アンプへ
      │         │
      └────┬────┘
           │
          GND
```

この仕組みを分圧と呼びます。つまみを回すとワイパーの位置が変わり、取り出す信号の電圧を調整できます。

ここで面白かったのは、可変抵抗自体が音声信号を増幅しているわけではないことです。アンプに渡す信号を弱めることで、結果的に音量を調整しているのです。

実際にスピーカーを駆動するのは、この後に接続するオーディオアンプの役割になります。

### アンプでスピーカーを鳴らす

音量を調整した信号は、オーディオアンプ IC の NJM2113D に入力します。

マイコンの GPIO から出力される信号だけではスピーカーを十分に駆動できないため、アンプを使います。アンプは電源から供給されるエネルギーを使い、入力された音声信号に応じてスピーカーを動かします。

今回の回路では、アンプの入力部分に次の部品を使用しています。

| 部品 | 役割 |
| --- | --- |
| C6（0.1 µF） | 音声信号の直流成分を遮断する |
| R2（10 kΩ） | アンプの入力抵抗 |
| R3（47 kΩ） | アンプの増幅率を調整する帰還抵抗 |

特に興味深かったのが、C6 の役割です。

PWM を RC フィルタで滑らかにしても、信号には直流（DC）成分が残っています。C6 は、この直流成分を遮断し、音声に相当する変化成分（交流成分）を次の回路へ通します。このような使い方を AC カップリングと呼ぶそうです。

また、R3 はアンプの出力の一部を入力側へ戻すための抵抗です。これを負帰還（Negative Feedback）と呼び、R2 と組み合わせて増幅率を決めます。

NJM2113D は BTL（Bridge-Tied Load）方式のアンプで、スピーカーの両端をアンプの出力（5番・8番ピン）に接続します。スピーカーの片側を GND につながない点も、今回新しく學んだことの一つです。

こうしてアンプで増幅された信号によってスピーカーが振動し、ようやく音として聞こえるようになります。

### コンデンサでアンプの動作を安定させる

もう一つ興味深かったのが、コンデンサを使った電源や回路の安定化です。

今回の回路では、アンプの周辺に次のコンデンサを配置しています。

| 部品 | 容量 | 役割 |
| --- | --- | --- |
| C7 | 1 µF（105） | 使用しない入力端子を安定させる |
| C8 | 4.7 µF | アンプ内部の基準電圧を安定させる |
| C9 | 10 µF | 電源電圧の比較的ゆっくりした変動を抑える |
| C10 | 0.1 µF（104） | 電源の高周波ノイズを抑える |

特に面白いと感じたのが、C9 と C10 を組み合わせた電源の安定化です。

アンプがスピーカーを動かす際には、電源から電流を消費します。電流の変化によって電源電圧が揺れると、音声にノイズが混じったり、動作が不安定になったりする可能性があります。

そこで、3.3 V と GND の間にコンデンサを接続し、電源電圧の変動を抑えます。このような対策をデカップリング（Decoupling）や電源バイパスと呼びます。

今回使用した C9（10 µF）は比較的ゆっくりした電源変動を緩和し、C10（0.1 µF）は高速な変動への対策として、アンプの電源ピンの近くに配置します。

最初は、コンデンサは電氣を蓄える部品という程度の理解でした。しかし、PWM の平滑化、直流成分の遮断、電源の安定化など、同じコンデンサでも接続する場所や容量によって役割が変わることが分かりました。

今回の実験では、実際にスピーカーから音を出すことができました。ノイズ低減の効果までは検証していませんが、まずはそれぞれのコンデンサの役割を理解できたことが収穫でした。

## AtomVM で音声を再生する

音声回路ができたところで、次は AtomVM から PWM を出力するプログラムを作りました。

今回の実装では、Elixir と C で役割を分けています。

- **Elixir**：再生する音源の選択、再生開始、完了確認を担当する
- **C（ESP-IDF）**：一定間隔で音声データを読み出し、PWM のデューティ比を更新する
- **Python**：練習用音源の生成や、音声データの取り込みを担当する

処理の流れは次のようになります。

```text
Python で音声データを準備
          │
          ▼
Flash に PCM データを格納
          │
          ▼
Elixir / AtomVM
（音源の選択・再生指示）
          │
          ▼
C / ESP-IDF
（PCM を読み出して PWM を更新）
          │
          ▼
XIAO ESP32-C5 の GPIO7
          │
          ▼
音声回路 → スピーカー
```

Elixir から C の処理を呼び出すために、NIF（Native Implemented Function）を使用しています。

音声を再生するには、PCM のサンプルレートに合わせて一定間隔で PWM を更新する必要があります。そのため、タイミングが重要な処理は C 側に任せ、ESP-IDF の GPTimer と LEDC を使用しました。

また、今回の音声 NIF は標準の AtomVM には含まれていないため、専用のカスタムファームウェアをビルドしています。

### 2 台で歌わせる

最初は 1 台で約 10 秒の練習用フレーズを再生していましたが、その後、友人から提供してもらったパパゲーノとパパゲーナの歌声を使って、2 台での再生にも挑戦しました。

それぞれの基板に担当する音声データを組み込み、別々のファームウェアとアプリを書き込みました。

- **Papageno（男声）**：16 kHz の男声音源を再生
- **Papagena（女声）**：16 kHz の女声音源を再生

今回はデバイス間の通信による同期は行わず、音源に含まれる休止時間を保持したまま、2 台をほぼ同時に起動する方法を採用しました。

実際に試してみると、2 台のスピーカーからそれぞれの歌声が聞こえ、掛け合いも再生できました。

ソースコードやファームウェアのビルド手順は、[GitHub リポジトリ](https://github.com/mnishiguchi/hello_atomvm_papapa) にまとめています。

## 音声データにもいろいろな形式があった

音声を再生する仕組みを調べる中で、音声データにもさまざまな形式があることを知りました。

最初は WAV や PCM という名前の違いをあまり意識していなかったのですが、調べてみると、サンプルレート・ビット深度・チャンネル数など、いくつもの要素があることが分かりました。

今回扱った音声データは次のとおりです。

| 音源 | 形式 | サンプルレート | ビット深度 | チャンネル |
| --- | --- | --- | --- | --- |
| LLM に生成してもらった練習用フレーズ | PCM | 8 kHz | unsigned 8-bit | mono |
| パパゲーノ（男声） | Raw PCM | 16 kHz | unsigned 8-bit | mono |
| パパゲーナ（女声） | Raw PCM | 16 kHz | unsigned 8-bit | mono |
| 参考用の二重唱音源 | WAV | 48 kHz | signed 16-bit | stereo |

それぞれの意味を簡単に整理すると、次のようになります。

- **サンプルレート**：1 秒間に音声の値を何回記録するか。16 kHz なら 1 秒間に 16,000 回。
- **ビット深度**：音声の値を何ビットで表現するか。8-bit なら 256 段階。
- **チャンネル数**：mono は 1 チャンネル、stereo は 2 チャンネル。

また、WAV と PCM は単純に別々の音声方式というわけではありません。

PCM は音声を数値で表す方式で、WAV は音声データを格納するファイル形式です。WAV ファイルの中にも PCM データを格納できます。

WAV には通常、サンプルレートなどの情報がヘッダーとして含まれます。一方、今回の `.pcm` ファイルはヘッダーのない生データ（Raw PCM）なので、再生するときに形式を指定する必要があります。

例えば、パパゲーノの音源を PC で再生する場合は、次のように指定できます。

```bash
ffplay -f u8 -ar 16000 -ac 1 song_male.pcm
```

ここで `u8` は unsigned 8-bit、`16000` は 16 kHz、`1` はモノラルを意味します。

特に注意が必要だと感じたのが、サンプルレートです。

例えば、16 kHz の音声データを 8 kHz として再生すると、再生速度が半分になり、音程も低くなってしまいます。サンプルレートを変更するには、単に数値を変更するのではなく、適切なリサンプリングが必要です。

今回、最初の練習用フレーズは 8 kHz で再生していましたが、2 台でのデュエットでは、提供してもらった歌声の 16 kHz を維持したまま再生できるようにしました。

また、歌手別の音源には冒頭に休止時間が含まれていました。これを取り除かずに使うことで、2 台をほぼ同時に起動したときに、元の掛け合いのタイミングを再現できました。

音声ファイルも、ただデータを読み込めばよいわけではなく、そのデータがどのような形式で記録されているかを理解することが大切だと分かりました。

## おわりに

今回は音声再生に絞って、電子回路や PCM・PWM の仕組みを一つずつ學びました。

最初は 1 台の XIAO ESP32-C5 から音を出す実験でしたが、最終的には 2 台でパパゲーノとパパゲーナの掛け合いを再生できました。

今後も、氣になった技術を小さな Hello World に分けて、少しずつ試していきたいと思います。
